# Repository description and topics template

Describe what the project does and who uses it. Keep descriptions short. Add
technology details only when they help someone understand the project.

## Description

```text
[What it does] for [who uses it]. Built with [main technology].
```

Remove unused placeholders before saving. Do not claim features, availability,
or results that the project does not have.

## Topics

```text
kodolabs, [purpose], [use-case], [language], [framework]
```

Choose relevant topics. Use lowercase letters, numbers, and hyphens. Avoid
confidential project names: topic names are public even on private repositories.
See [GitHub's topic guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics).

## Example: bonjou-cli

```text
Description:
Encrypted local-network chat and file sharing for the terminal. Built with Go.

Topics:
kodolabs, golang, cli, file-sharing, local-network, end-to-end-encryption
```

Use the project's approved assets for its social preview. Keep organization
branding separate from product branding. Preserve repository visibility,
licenses, and attribution when changing metadata.
